# 2.6.5：私密状态关联与完整性核对

## 真实页面发现

2026-11-04通过用户已登录的抖音创作者中心正常界面逐步加载，清空日期和搜索，选择全部审核状态后，列表显示到底，共204张作品卡。DOM中173张有明确私密标记，31张显示已发布。顶部仍标称293条；未通过审核筛选显示0条。89条差额原因尚未确认，不能推定删除、审核不通过或已采齐。

CLab旧版204条中：71条已排除、96条为播放0但有互动、5条零播放待核实、32条可分析。旧总览把前71条也加入待核实，因而错误显示172条都待处理。

直接比对发现，部分旧版“播放异常”记录在源页已明确私密，显示指标“-”。封面变体或标题换行可能使旧版严格标题+封面关联漏掉该状态。因此需先修正状态关联，不能把每一条0都当作丢了播放数据。

## 修正

- 状态关联继续要求唯一匹配：完整标题（仅归一化空白）+封面；封面版本不同则可用唯一标题+源页面发布时间分钟。歧义、缺日期或时间不同不自动关联。
- 源页明确已发布时也记录public，可更新旧的私密状态。不会由0推定私密。
- 总览单列不可公开作品，不再作为待补采；真正待核实按播放缺失、零播放、0播放但有互动列出。
- 采集任务字段覆盖不再把已确认私密/不可公开作品算作公开有效覆盖。
- 分别展示可见清单核对与平台标称总数。204张源卡到底不等于293条全量完成，差额仍保留提示。
- 缺作者标识时，仅当本批全部ID已在此前人工核对入库的采集中出现，且在抖音账号间没有归属歧义，才自动刷新已有作品。一条新ID或归属不明即保留整批核对，不按标题猜作者。

## 验证与边界

使用不含个人信息的204条模拟记录走通：旧71条排除+101条待核实+32条可分析 → 正确关联后173条排除+31条可分析+0条待核实；历史指标未被清空或改成假0。这是回归测试，尚不是用户数据库更新结果。

真实源页调查完成；新代码需覆盖后重采，再核对用户数据库是否达到173/31，以及有无仍无法关联的作品。89条差额未解决，本包不声称全量293条完成。官方“导出数据”入口尝试未获得文件，不将其写作成功补数。

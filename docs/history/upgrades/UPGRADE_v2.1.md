# CLab 2.1 · 抖音与B站独立空间

两平台分别组织作品、采集状态、分析目标与输入字段。个人首页不再设置“全部平台”；跨平台仅在用户主动关联内容后单独比较，不混合原始指标排名。

| 项目 | 抖音空间 | B站空间 |
| --- | --- | --- |
| 采集路径 | 创作者作品列表、公开作品页补互动 | 公开空间列表、视频详情、可选本人创作中心 |
| 六维卡 | 播放、点赞比例、评论比例、收藏比例、分享比例、完播率 | 播放、点赞比例、评论比例、收藏比例、分享比例、投币比例 |
| 进阶指标 | 5秒完播、2秒跳出、平均观看时长 | 投币、弹幕 |
| 输入与分析 | 不提供投币/弹幕目标 | 不默认提供完播/跳出目标 |

分类体系、战力卡样本与历史位置仍按平台、账号分别计算。通用的字段存储与图表组件可以复用，不表示两平台的统计口径等价。

## 抖音采集修复

- 同时识别 `metrics`、`statistics`、`stats` 中的明确字段，新增收藏数从采集、旧表、历史记录到作品库的完整保存路径。
- 部分更新不再清空已有发布时间；只有发布时间更新时，也会同步到作品库。比例仅接受0–1数值或明确的百分比字符串，不猜数字单位。
- 正常翻页结束、总数不一致、连续停滞、停止、中断、部分完成分别记录状态；停滞时尝试一次正常页面刷新。单任务锁避免重复启动浏览器。
- 补采先重读创作者列表，刷新播放量，再尝试最多20条缺项作品的正常公开页面。每轮有时间预算，按历史尝试次数优先处理未试过的作品，避免总卡在同一批。
- 公开视频响应和页面JSON只接收已在当前作品列表中的视频ID，忽略推荐视频。每个实际取得字段单独记录观测时间，不用合并旧值伪造新观测。
- 公开互动读取不等于取得后台完播率。没有留存数据时，该维度保持缺失；已有至少3个可比维度、至少3条同组作品仍可探索画像。

## 首页与进度

未解锁时先显示六项真实数值和缺项，补采按钮直接放在旁边。采集进度每3秒检查，数据变化时刷新工作台；进程已退出时不会继续显示“正在采集”。侧栏只保留简短操作，详情默认收起，并去掉页面下方重复的平台标题。

## 升级与使用

1. 关闭旧程序和旧采集窗口，备份 `local` 文件夹，将其副本放入新目录后启动。
2. 选择“抖音空间”，在首页点击“补齐互动数据”，或从侧栏打开完整同步。在窗口登录并进入作品管理，遇验证由你完成。
3. 已有作品按视频ID更新，不需要清空重导。补采先刷新列表，保证播放与互动尽量来自同一轮；每轮未完成时可再次启动。
4. B站使用自己的空间和补采入口。需要跨平台比较时，到“创作进阶 → 跨平台关联”确认同一内容的发布版本。

## 验证边界

本地检查覆盖收藏迁移、稀疏更新、比例口径、截图中的203/292部分完成状态、进程退出状态、按ID约束的模拟浏览器补采、首页操作以及平台切换。它们不能证明你本机上的抖音页面已经成功采齐292条作品；本轮未使用真实登录账号进行线上端到端验收。平台页面、登录、验证与字段可见性仍影响结果，缺失不会被补成0。

# 2.6.8 累积补丁：播放规模与点赞转化同时可见

适用于2.6.5、2.6.6、2.6.7，包含此前状态关联和私密作品提示，不需要依次安装小版本。关闭CLab，按压缩包原路径覆盖到app.py所在目录，重新启动即可。不是独立完整安装包，不覆盖local个人数据。

## 本轮问题

数量位置与互动效率分开显示，容易把播放规模误读为互动转化。本版开始将两条线同时呈现；私人作品的原始明细不随公开文档发布。

## 新呈现

- 同一张六轴图同时画数量位置和互动转化位置，分别使用绿线与橙线；各轴同时标出两种位置。
- 轴改为播放触达、点赞、评论、收藏、分享、完播（B站为投币），避免把点赞量直接叫“喜欢”、把播放量当分享。
- 图旁常显播放、点赞、两位小数点赞率，以及同组点赞率中位数、当前相对比例和参照数。
- 当播放达到或超过同组中位数，而点赞率低于同组中位数时，明确提示“播放较高、点赞转化偏低”，不只强调优势维度或综合位置。
- 比较限定同账号、平台、体裁、观察口径，排除当前作品及不可公开记录，不强制按作品年龄分组。不是全站标准或内容质量评级。
- 点赞等互动转化轴及效率综合排名排除播放不足1000的样本。原始比例仍显示；2播放1点赞不会获得高转化评分。1000是工具的稳定性门槛，并非平台规则；诊断还需要至少3条其他有效作品。
- 原始点赞率只描述行为，不直接证明观众是否喜欢内容，不能单凭这个数字推断原因。
- 导出PNG保留战力卡，加入双线、原始点赞率与差异解释。docs/previews/reach_conversion.png使用明确标注的演示数据，可查看示例效果。

新版本经过自动回归及示例渲染检查，需覆盖后再对用户真实作品复验。并未修改用户作品的实际点赞/播放数据，也未宣称解决89条平台标称数量差异。

最终验证：234项回归通过。177条警告为环境包元数据弃用提示及既有空样本均值提示，无测试失败；新模型覆盖高播放低转化、2播放1点赞不评分、参照隔离、默认图直接显示短板和PNG导出。演示PNG已逐图检查。

# CLab 1.9 · 可验证的创作复盘循环

这次将八个问题落实到采集、解释、对比和实验流程。保留明暗切换、B站空间、原有图表、手动输入和分类。工程实现已经完成；未使用真实登录账号完成平台端到端验收，不能将本地测试等同于线上采集保证。

## 八项改造

| 问题 | 本次变化 | 使用入口 |
| --- | --- | --- |
| 采集可靠性不足 | B站快速导入、失败/缺项定向重试、采集预算、实际进度估时；区分缓存已有值与本轮取得值。封面按作品ID绑定，并检测原图更换；增加逐字段人工核对记录。 | B站空间；使用说明中的验收面板 |
| 新用户没有足够数据可看 | 1–4条也展示三条事实与下一步动作；六维图可选至少3条的探索模式。 | 数据分析 → 成长面板 |
| 六维图含义不稳定 | 同时展示原值、样本数、历史位置，缺失不补零；支持冻结参照组，披露高度相关维度，不合成能力总分。 | 作品表现画像 |
| AI只理解标题 | 可选择真实缓存封面、上传关键帧与文案，或用本机FFmpeg提取视频0/3/10秒画面；返回可观察事实、待验证假设、实验建议和证据范围。 | 素材复盘 |
| 学习对象链路不完整 | 浏览器执行真实平台公开搜索，候选标注来源与粉丝规模，优先同量级和稍领先账号；保留人工添加、AI待核验候选及B站参考作品采集。 | 学习对象 |
| 分类入口重复 | 共用“分区 → 细分赛道 → 具体主题 → 表现形式”编辑器，未选择时保持未知；AI建议可人工修正。 | 作品编辑、分类、成长面板 |
| 指标观察时间混乱 | 每个实际取得字段独立记时；当前累计、24小时、7天、30天分开比较，旧合并快照不补造历史。 | 数据分析窗口选择 |
| 挑战只是记事 | 将实验关联到基线作品和改动作品，在相同观察窗口自动复盘；冻结首次可评估基线及证据，保留状态、笔记、待采集提示。 | 创作实验 |

## 建议使用顺序

1. 关闭旧程序，备份旧 `local` 文件夹，将副本放入新目录后启动。首次迁移会添加新表，不清空旧作品。
2. B站先快速导入，检查账号粉丝数、作品指标和封面；查看缺项后使用定向重试。在验收面板手动核对源页面中的字段，留下通过或失败记录。
3. 在统一分类中确认赛道，先看三条事实提示，再查看交叉分析、六维图或学习对象。需要长期观察时保存固定参照组。
4. 从素材复盘或自己的判断提出一个改动，建立实验，关联基线作品与新作品，选择统一的24小时、7天或30天窗口，在到期时重新采集。

## 口径与实际限制

- 固定窗口允许的采集偏差：24小时±2小时、7天±12小时、30天±24小时。一个比例中的分子、分母须在两小时内实际观测。缺失值保持缺失，不从当前累计推算历史值。
- 固定窗口要求精确发布时间与时区。日期不完整、历史合并快照、未提供 `observed_at` 的旧CSV仍可查看累计数据，但不能成为固定窗口观测。现在补采无法恢复已经错过的过去窗口。手动与CSV可填写真实采集时间，例如 `2026-10-27T08:00:00+08:00`。
- 小样本结果用于形成下一次创作假设，不能说明改动导致了增长。六维图是同组分布位置，保存参照后才有稳定标尺；相关维度不能视为六种独立能力。
- 平台页面、登录状态、风控和数据可见权限都会影响采集。B站本次增加定向重试；抖音新增真实字段观测记时，未宣称具备相同的重试流程。未取得的粉丝、完播率等字段不会估算补齐。
- 公开搜索得到的是候选，未经赛道与头部地位核验；AI候选同样需要验证。没有官方排行榜或完整赛道数据库，不能保证自动找全头部博主。粉丝缺失时显示规模未知。手动对标仍可用，观察窗口不一致时不作数值对比。
- 素材分析需要支持图片的模型与用户配置。仅在明确点击同意发送后，发送所选最多4张图片和最多12000字文案；本地视频上限50MB，仅提取画面，不上传原视频。未安装FFmpeg时可直接上传关键帧。几张画面不代表完整理解整条视频。
- 到期提示只在应用打开时计算；没有后台自动采集、系统通知或自动发布。真实数据足够时实验才展示比较，缺失或窗口错过会说明原因。
- 验收面板的人工核对记录仅证明所核对的字段；本地自动测试覆盖数据口径、迁移与交互逻辑，不能证明所有账号、平台页面均能成功导入。

## 启动

Windows 解压后双击 `start_windows.bat`。手动运行：`python -m streamlit run app.py`。依赖安装方式见README。可选素材视频提帧需另行安装FFmpeg。

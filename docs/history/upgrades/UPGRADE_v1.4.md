# CLab 1.4 · 真实封面与内容交叉分析预览

## 更新与启动

先备份旧目录的 `local` 文件夹。解压新包，复制该文件夹到新目录，再运行 `start_windows.bat`。首次启动自动增加标签表和封面缓存表，保留原账号、作品和指标快照；不需要删除数据库。

## 真实封面

- 兼容作品顶层和 `video` 下的 cover / origin_cover / dynamic_cover 图片结构。
- Chrome 扩展也传递实际封面 URL，并尝试通过页面的视频 ID / 链接补充图片 URL。更新扩展后需要在扩展管理页重新加载。
- 建议使用侧栏「打开抖音同步窗口」：进入作品管理，等待缩略图加载。正常页面返回的匹配图片响应会保存到本地；可见图片也会按视频 ID 或实际封面 URL 匹配，裁取图片本身并保存。下次优先显示缓存，避免完全依赖易失效的远程图片地址。
- 不按卡片序号或模糊标题绑定图片。不主动重放接口，不绕过登录。没有明确绑定依据时保留待补全。
- 作品库 → 作品详情可手动上传原封面。须有视频 ID；支持 PNG / JPEG / WebP，5MB 以内。
- 缓存与用户数据一起存储在本地 SQLite 数据库；不包含在发布包内。

**验证边界：** 本次验证覆盖封面字段解析、图片校验和数据库缓存；没有在你的已登录抖音页面做实际采集验收。页面若只使用背景图、没有可识别的视频 ID，且接口缺少图片地址，该封面仍需补录。扩展路径目前补全 URL，长期本地缓存由内置同步窗口或手动上传完成。远程 URL 单独存在时仍可能失效或受防盗链限制。

## 从排行榜转向内容策略

1. 数据分析 → 设置账号赛道；批量选择作品，填写分类和主题。COS 可记录“变装 / 剧情 / 舞蹈”和角色/IP；知识类可记录“教程 / 观点 / 测评”等自定义分类。
2. 作品详情可填写视频秒数；未知时不推算。CSV 新模板也支持 track、category、topic、duration_seconds、cover_url。标题不会被自动当成可靠的内容分类。
3. 选择账号、作品年龄区间和目标指标，查看以下分析。

| 分析 | 回答的问题 | 统计依据 |
| --- | --- | --- |
| 分类分布图 | 哪类内容表现稳定，而非只有一条爆款？ | 每条作品、中位数、四分位数、有效样本数 |
| 交叉热力图 | 哪种分类在什么时长、时间段或角色/IP下表现更好？ | 组合内指标中位数；低样本留空，可选择组合查看作品 |
| 流量 × 质量散点图 | 高播放是否伴随高点赞、分享、收藏或留存？ | 每条作品的累计播放与所选质量指标，中位数参考线 |
| 跨平台复用对比 | 同一内容在哪个平台更超过自身日常水平？ | 手动关联作品；播放除以同账号、同平台、同年龄区间中位数 |
| 赛道建议 | 下一轮该验证哪种形式？ | 两类各至少5条有效记录；同账号、平台、作品年龄区间比较 |

比例指标图中的 0.05 表示 5%。发布时间默认按中国时区，也可切换。作品年龄用“采集时间减发布时间”计算，不用今天的日期替代采集日期。首次默认排除不足7天与年龄未知的作品，可自行调整。

## 建议输出

数据充足时：显示分类差异 → 原始指标、中位数和样本数 → 对应赛道实验方案 → 验证方法与局限。例如 COS 对比同一角色的“成片先展示”与“变装铺垫”，用后续3条作品在发布第7天采集的指标复盘。

样本不足时：明确显示缺口，只给“赛道实验模板”，不把常识伪装成你的账号结论。现在是可审计的规则建议，不是已接入的内容理解模型或实时热点推荐系统。

## 口径与限制

- 主要输入仍是最新累计指标，不是统一的发布7天指标；同年龄区间内依然存在累积时间差异。长期需要持续记录快照，建立固定观察窗口。
- 分类差异不能证明内容因果；投流、角色/IP热度、粉丝构成和发布时间等仍可能影响结果。图表帮助提出假设，不保证爆款。
- 跨平台指数的参照是各账号自己的历史作品，基准至少5条；不是直接比较两平台绝对流量价值。尚无真实同行数据库，也不会生成虚构同行基准。
- 标签由用户确认。自动识别视频画面、内容转录、角色识别、训练赛道模型、自动热点情报、自动发布本轮未实现。
- 旧版工具保留；B站仍采用 CSV / 手动导入。
